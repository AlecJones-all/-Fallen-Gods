# 18 动作文件生产与打包计划

> 范围：只生产**动作文件**并打成可上传的包。
> **不接入游戏**——`player.gd` / `player_visual.gd` / `player.tscn` / `tuning.json` / `rogue_knight_v2.tscn` 一律不动。
> 依据：`docs/17_武器与蓄力设计计划.md` 第 3–4 节，加上本轮实测（生成器的保存方式、`.gitignore` 的分发限制）。

---

## 一、边界：什么叫"先做好文件，不动游戏"

| | 内容 |
|---|---|
| ✅ 允许 | 新增 `tools/build_anim_pack.gd`、`tools/verify_anim_pack.gd`；新增 `dist/` 目录；写 manifest / README / 预览图 |
| ❌ 不允许 | 改 `build_anim_v2.gd` 的 `TARGET` 输出、改任何 `player*.gd`、改 `tuning.json`、改 `rogue_knight_v2.tscn`、改 `attack_blade` 时长 |
| 允许但只读 | `build_anim_v2.gd` 里的 `_clip` / `_sample` / `_load_src` 逻辑（复制到新脚本，不改原件） |

### ⚠️ 一条必须绕开的硬约束（实测）

`tools/build_anim_v2.gd` 第 58–71 行：

```gdscript
var ap := _tgt.find_child("AnimationPlayer", true, false)
ap.add_animation_library("", lib)
var packed := PackedScene.new()
packed.pack(_tgt)                      # ← 整个玩家场景重新打包
ResourceSaver.save(packed, TARGET)     # ← 覆盖 rogue_knight_v2.tscn
```

**每次运行都会重写整个玩家场景。** 所以"加动作但不接进游戏"不能直接跑它——跑一次游戏就变了。

正确做法：新写一个导出器，`load` 场景只为了拿骨骼名和 rest 姿态，**只 `ResourceSaver.save(lib, "xxx.tres")`，不 `pack`、不 `save` 场景**。产物是一个独立的 `AnimationLibrary` 资源，谁要用谁自己 `add_animation_library()`。

技术上这是成立的：clip 里的轨道路径是 `Skeleton3D:<骨名>`（相对 `AnimationPlayer.root_node`），不绑定具体场景，只要目标骨架的骨名一致就能播。

## 三、生成流程（4 步，每步可独立验证）

### Step 0｜修源选择（唯一必须动的代码，且只动构建工具）

`_load_src()` 第 122–123 行取 `get_animation_list()[0]`。对纯动作包没事，但 `Jump Attack.fbx` 是混合包：

```
[0] Take 001     3.33s  ← 内嵌角色的静帧
[1] mixamo_com   3.80s  ← 真正的跳劈
```

改成按名优先取 `mixamo_com`，取不到再退回 `[0]`：

```gdscript
func _pick_anim(ap: AnimationPlayer) -> Animation:
    var lst := ap.get_animation_list()
    for n in lst:
        if str(n).begins_with("mixamo"):   # mixamo_com / mixamo.com
            return ap.get_animation(n)
    return ap.get_animation(lst[0]) if not lst.is_empty() else null
```

不修这条，`attack_axe_heavy` 会是一段**静止**的动作，而且**不报错**。

### Step 1｜建导出器 `tools/build_anim_pack.gd`

- 复制 `build_anim_v2.gd` 的 `_load_src` / `_sample` / `_clip` / `_make` 逻辑（原文件不动）
- 场景只 `load` + `instantiate` 拿 `Skeleton3D` 与 rest 姿态，**绝不 `pack` 场景**
- 输出：`ResourceSaver.save(lib, "res://dist/anim_pack_v1/rogue_knight_anims.tres")`
- 新增 `pack.json` 同步落盘（生成参数原样记录，便于以后复现）

### Step 2｜生成后立即自检

每段生成完当场校验，不通过就中止（不要"先存了再说"）：

| 检查 | 期望 |
|---|---|
| 轨道数 | 53（22 骨旋转 + 1 Hips 位移 + 其余） |
| loop 段首末帧 | 四元数差 < 0.5° |
| hold 段 Hips 位移 | \|Δy\| ≤ 0.012 m，\|Δx,z\| ≤ 0.002 m |
| 数值健康 | 无 NaN / Inf |
| 骨骼名 | 全部落在 22 骨映射表内（防"野骨骼"混进包） |
| 时长 | 与 spec 表一致，误差 ≤ 1 帧（1/30s） |

### Step 3｜出预览图

复用 `tools/preview_scene.gd` 的思路，每段取 3 帧（起手 / 中点 / 收势），拼成一条条对比带。这一步**只产出图，不改场景**。

## 四、包的结构

```
dist/anim_pack_v1/
├── rogue_knight_anims.tres     主交付：16 段 AnimationLibrary（约 1.0–1.3 MB）
├── manifest.json               清单：每段元数据 + 来源 + 参数
├── README.md                   3 行用法 + 骨骼映射说明 + 许可
├── preview/
│   ├── charge_hold_axe.png     每段一条 3 帧对比带
│   └── ...
├── verify.txt                  verify_anim_pack.gd 的完整输出（自证）
└── demo/
    └── anim_viewer.tscn        独立预览场景（可选，不含任何游戏逻辑）
```

**为什么是 `.tres` 文本格式**：可 diff、可 review、能看到某一段是哪次改动引入的。二进制 `.res` 小 30%，但以后没人说得清包里那一段是哪个版本。**建议 `.tres`。**

**`demo/anim_viewer.tscn` 值不值得放**：值得。它让收到包的人（队友 / 评委 / 未来的你）**不用跑游戏**就能一段段看。成本很低——一个 `Skeleton3D` + `AnimationPlayer` + 一个 `OptionButton` 切 clip。

## 六、合规：这个包能放什么、不能放什么

你的 `.gitignore` 已经写明了立场：

```
# Mixamo source FBX files are not redistributed
assets/anim_src/*.fbx
# Third-party source asset packs are kept local only
assets/anim_src/*/
```

所以：

| | 判定 |
|---|---|
| ❌ 原始 `assets/anim_src/*.fbx` | 不放。Mixamo 允许在项目里用，但不允许把动作文件本身当素材再分发 |
| ❌ `bulky-knight` / KayKit 等第三方包原文件 | 不放 |
| ✅ 派生出的 `AnimationLibrary`（骨骼局部旋转曲线） | 放。这是"跑在你角色骨架上的动作数据"，不是原作者的资产文件 |
| ✅ 骨架与蒙皮（`build_rig_v2.gd` 的产出） | 放。Rogue Knight 的网格是 CC BY 4.0，**必须署名** |
| ⚠️ 预览图 | 能放（是你的角色渲的），但要带署名 |

**两档方案**：

- **严格版（公开仓库 / 比赛提交）**：只放 `.tres` + manifest + README + 许可清单，不含任何 FBX。上面结构图就是严格版。
- **宽版（团队内部网盘）**：可以额外带 FBX 方便队友对照。但既然严格版也能用，**建议只做严格版**，省得以后分不清哪个包能公开。

### 实现中发现的三个坑（都已修）

1. **`build_anim_v2.gd` 取 `get_animation_list()[0]` 会拿到静帧** —— `Jump Attack.fbx` 是模型+动作混合包，`[0]` 是内嵌角色的 `Take 001`（3.33s 静止），`[1]` 才是 `mixamo_com`（3.80s 真动作）。新导出器改为按名优先取 `mixamo_com`，且**没有改原件**。
2. **`trim0/trim1` 是相位不是秒** —— 原脚本的 `0.30 / 0.78` 指源片段的 30%/78%，不是 0.30s。第一版 hold 按秒取值，取到了错误的姿势。
3. **`sweep` 在片段首帧恒为 `-sweep`** —— 想"起手不拧"，必须让该帧的 sweep 等于目标值；新片段改用 `sweep_ramp`（从 0 单方向转到 sweep），旧片段行为不变（等价性自检守护）。
