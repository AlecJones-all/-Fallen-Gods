# 22 人物与怪物制作规划

> 范围：只规划人物、可玩角色、敌人与怪物，不包含场景制作。
>
> 目的：把剧情角色、现有模型、生成缺口、可验证动作与接入顺序放到同一张主表中。本文是制作计划，不表示任何候选模型已经进入游戏。
>
> 剧情依据：[三身份设定](../故事线/03_三个开局身份%20(2).md)、[十五关主线](../故事线/04_十五关主线.md)、[角色档案](../故事线/07_角色档案.md)、[支线设计](../故事线/05_支线.md)。资产依据：[资产库总表](21_资产库总表.md) 与 [三主角接入计划](20_三主角接入计划.md)。

## 一、状态字段与验收口径

| 字段 | 含义 |
|---|---|
| 候选 | 文件存在，尚未说明可在游戏中使用 |
| 已实查 | 已读取网格、骨骼或动画元数据，仍须在 Godot 实播 |
| 可试接 | 有可用于第一轮导入的模型或复用底模 |
| 缺口 | 当前没有满足剧情、性能、骨骼与授权条件的候选 |
| 已否决 | 不进入可玩或战斗正式包，保留原始文件和否决原因 |

每个正式角色完成前必须同时通过以下验收。

1. 角色在项目等距镜头、暗场和战斗距离下能与背景区分轮廓。
2. 战斗单位完成待机、移动、受击和退场。剧情单位完成其主表中的关键动作。
3. 角色的剧情形态、分支形态和重复出场共用命名与材质规则，玩家能认出是同一角色。
4. 模型来源、使用许可、署名要求及导入源路径写入资产记录。
5. 导入 Godot 后实测面数、贴图尺寸、骨骼、动画和帧率。候选文件的目录信息不能替代这一步。

## 四、按可验证切片推进

### 第一批：三主角、炉边关系与节点 01 至 05

1. 验证林野和雀试装模型能使用 mixamo 骨架动作，阿舍尔保留现有骨架与入口。
2. 完成萨姆的敌对与炉边两段演出，确认同一模型跨状态可辨认。
3. 用 `cultist-tpose` 做灰烬主教的跪向笼子原型，同时做莉薇娅上层剪影与左手动作。
4. 制作炉婆二维定稿与递食动作原型，再进入完整模型生产。
5. 建立税道的近战、远程两种敌人的攻击前摇和轮廓验收。
6. 林野线节点 03 验证欧玻洛斯找零多给旧币；雀线同节点验证龙影首次挡刀与鳞片黯淡。

**检查点**：分别从三个身份回放 01 至 05 的关键镜头，所遇角色在首次出现时可辨认，节点 05 的“主教跪向笼子”能在不读说明文字时成立。

### 第二批：节点 06 至 10 与换生灵路线

1. 食梦狼完成动作实播、梦境污染材质与回声吐出镜头。
2. 蓟相、赫恩完成底模选择，优先验证免债反应和停战让路。
3. 复用第一批的龙影援护，对照完整龙形，验证翼尾动作并决定绑定范围。
4. 让法庭和神性敌人与教会敌人在等距战斗距离下可区分。

**检查点**：节点 07、09、10 的三只 Boss 各有一个可解释剧情的非攻击动作，停战和免债分支不会被默认战斗状态吞掉。

### 第三批：节点 11 至 15、终局和重复游玩形态

1. 领唱人、塞维林投影、门房审判和眠者之影分别完成可读原型。
2. 莉薇娅“熄灯者”、克莱门斯沉沦线、维斯佩拉受伤形态按条件触发组织为同角色变体。
3. 七席为每位成员建立轮廓、可说服退场和复用骨架的清单。
4. 苏醒之心把三段身份记忆的选择、反馈和收束做成完整垂直切片。

**检查点**：三条终局路线使用不同的主敌和胜利表达，终局形态的来源、许可与性能记录完整。

## 五、生成、动作与导入流程

| 阶段 | 选择 | 产物与通过条件 |
|---|---|---|
| 角色视觉定稿 | 使用已配置的 `imagegen` | 每个原创缺口先出正、侧、背与等距游戏镜头参考。第一批顺序为炉婆、莉薇娅、正式主教 |
| 图转 3D | `meshy-3d-generation` Skill（通过 Meshy CLI 运行） | 仅在二维定稿通过后生成单角色样品。建议炉婆作为第一件样品。生成结果仍是候选，必须经过下述审查 |
| 批量生成或任务查询 | Meshy MCP | 用于提交、轮询和下载已批准的 Meshy 任务。MCP 需要有效的 `MESHY_API_KEY` 才能实际调用，未配置密钥时不得声明生成已完成 |
| 技术审查 | 现有独立审计工程与 Godot 导入 | 记录三角面、贴图、骨骼、动画、包围盒和授权。超过性能预算、无骨骼或许可不明的模型回到候选或否决状态 |
| 动作接入 | 现有 `dist/anim_pack_v1`、动作构建脚本及 Godot 场景 | 人形分为自建骨架和 mixamo 骨架两条导出路径。四足、翼尾和异形先单独验证，不假定人形动作能直接复用 |
| 游戏验收 | `scenes/player/`、`scenes/enemies/` 与现有探针 | 每个切片录制或截图同机位的待机、移动、关键剧情动作和战斗动作，满足暗场轮廓与性能目标后才可标为已接入 |

## 六、授权与资产记录规则

1. 每个导入资产保留原始下载目录，禁止以“模型已经能打开”替代来源记录。
2. 记录来源页、许可文本、作者署名、是否允许比赛展示与是否允许衍生修改。
3. 使用同人设定参考的赫恩候选不作为正式提交资产，直到版权与署名条件得到确认。
4. Meshy 或其他生成资产记录所用参考图、提示词版本、生成任务标识、导出日期及后续人工修改。未经确认的生成模型保持候选状态。
5. 更换候选模型时更新本表和资产库总表。角色档案只在剧情本身的视觉事实发生变化时更新。
