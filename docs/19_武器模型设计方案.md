# 19 武器模型设计方案（连弩 / 斧）

> 范围：只设计**两把武器的模型**（几何 + 材质 + 挂点）。
> 本文不改代码、不改场景、不改动画包。所有改动都等你看完拍板。
> 依据：`docs/03_风格改造方案.md`（材质与规格）、`tools/build_rig_v2.gd`（现有实现）、`CHARACTER.md`（已知问题）、实机渲染。

---

## 一、现状（先对齐事实）

| 武器 | 现在是什么 | 问题 |
|---|---|---|
| **剑** | `Rogue Knight.fbx` 里的 `Cube_009`，1.95m 大剑，**蒙皮到右手**（不是挂在 socket 上） | 自带绿色辉光，与"烬纹暗红"设定冲突（已知问题 1） |
| **连弩** | `build_rig_v2.gd::_make_crossbow` **代码拼的 6 个 BoxMesh**：弩身 0.055×0.06×0.42 / 握把 / 左右弩臂 0.27×0.022×0.05 / 弦 0.5 / 弩箭 | ① 握持偏斜（已知问题 2）② 臂展 0.54m 偏大 ③ 只有三个**纯色**材质（wood 0.16,0.17,0.2 / metal 0.32,0.36,0.42 / glow 青 0.55,0.9,1.0），没有贴图 → 看起来像塑料 |
| **斧** | 无。`bulky-knight` 包里有个 `Axe_LP` 静态网格（AABB 0.00×0.06×0.03，无骨骼） | 没进骨架、没对轴、没接贴图 |

**关键约束**：剑不能动。它不是挂在 `socket_weapon.R` 上的节点，而是**按骨骼权重蒙在右手上**的网格——换位置等于改蒙皮权重，成本远高于收益。

## 二、为什么建议"继续用代码造"，而不是建模软件

你这套资产全是代码生成的，这不是巧合，是一条已经跑通的链：

| 环节 | 工具 | 产出 |
|---|---|---|
| 骨架 / 蒙皮 | `tools/build_rig_v2.gd` | 36 骨 + 4 网格 + 弩 |
| 贴图 | `tools/bake_textures.gd` | 7 种 256×256 albedo+normal |
| 动作 | `tools/build_anim_pack.gd` | 19 段动画库 |
| 材质 | 三平面世界映射 | **不需要 UV** |

一旦引入 Blender 网格，就多出两个东西：UV 展开、以及"改尺寸要重新导出"。而你现在改任何东西都是**改一个数 + 重跑脚本**。这就是为什么连弩当初是代码拼的。

所以本方案两把武器都走**程序化几何**，贴着现有 7 种材质走。唯一例外是斧——下面单独说为什么我还是给了 `Axe_LP` 这条路。

## 三、连弩设计

### 3.1 尺寸（收紧到 Q 版比例）

角色 4.5 头身、身高约 1.8m，武器不能按真人比例做。

| 部位 | 现状 | 建议 | 理由 |
|---|---|---|---|
| 弩身长 | 0.42 | **0.38** | 缩短 10%，减少"端着一根棍"的感觉 |
| 弩身截面 | 0.055×0.06 | 0.048×0.072 | 加高变窄，更像弩槽 |
| 臂展（两臂总宽） | 0.54 | **0.44** | 关键：现在比肩膀还宽，俯视角下糊成一团 |
| 单臂 | 0.27×0.022×0.05 | 0.22×0.020×0.042 | 弧形化（下详） |
| 握把 | 0.05×0.15×0.055 | 0.045×0.13×0.05，前倾 15° | 现在 12°，前倾多一点更"握" |
| 弦 | 0.5 直棍 | 0.40，随臂形微弯 | |
| 弩箭 | 有 | 保留，长度 0.30 | 已装填状态是卖点 |

### 3.2 要补的五个件（现在完全没做）

| 件 | 尺寸 | 作用 | 做法 |
|---|---|---|---|
| **弩机（扳机室）** | 0.06×0.07×0.09 | 弩身下方一块凸起，是"这是弩不是木头"的核心识别点 | 1 个 BoxMesh + 1 个小圆柱当扳机 |
| **扳机护圈** | 半径 0.03 的缺口环 | 手能握进去 | TorusMesh 半环 或 3 段小 Box |
| **箭槽（槽口）** | 宽 0.03、深 0.01 | 弩箭"卡在槽里"而不是"浮在上面" | 在弩身上表面挖不出来，就用两条薄侧壁夹出来 |
| **瞄具** | 0.02×0.03×0.005 竖片 | 前端小立片，仰视时可读 | 1 个 Box |
| **绑绳** | 3 圈 | 弩臂与弩身的绑扎，暗示"手工打造" | 3 个薄 Torus 或 Cylinder |

补完之后零件数从 6 → 11，三角面约 400（现在约 72），仍然极轻。

### 3.3 弩臂改成微弧（这一条最关键）

现在弩臂是**两个直 Box**，所以从任何角度看都像"两个横条"。改成弧形只需要把一个 BoxMesh 换成 3 段带 8°/16° 递进角的短 Box，或者直接用一个 `ArrayMesh` 生成 5 段折线。

**弧 + 后掠（15°）** 是弩的剪影特征。直条无论怎么调材质都不会像弩。

### 3.4 材质（换掉纯色，用现成的三平面贴图）

| 部位 | 材质 | 说明 |
|---|---|---|
| 弩身 / 弩机 | `iron_rust` | 现有 256 三平面，铜绿斑驳 |
| 弩臂 | `iron_rust`（tint 偏冷 0.85,0.85,0.9） | 与弩身同图不同 tint，符合"材质靠参数区分"规则 |
| 握把 | `wood_dry` | 干木纤维 |
| 绑绳 / 弦 | `cloth_rot` | 腐布，比纯色更像绳 |
| 弦线 | `bone` | 骨白细线，比黑线在暗场景里可读 |
| 弩箭 | `bone`（杆）+ `iron_rust`（镞） | |
| 烬纹发光 | **暗红** `Color(0.55,0.10,0.08)`，energy 1.4 | 替换现在的青色，见第六节 |

### 3.5 挂点（不动骨骼，只加 pivot）

现在：`WeaponAttachment`（`BoneAttachment3D`，绑 `socket_weapon.R`）→ `Crossbow` 直接挂上去，共用大剑的朝向。

**建议改成**：

```
Skeleton3D
└─ WeaponAttachment (BoneAttachment3D → socket_weapon.R)
   ├─ XbowPivot   (rotation: 弩口朝前 -Z, 仰角 -3°, scale 1.0)
   │  └─ Crossbow
   └─ AxePivot    (rotation: 刃朝斜下前, scale 1.0)
      └─ Axe
```

**为什么是 pivot 而不是新增骨骼**：
19 段动画里有 `socket_weapon.R` 的轨道。新增骨骼会让这些轨道对不上，**整套动画要重出**。而 pivot 是普通节点，动画完全不受影响，每把武器还能各调各的角度和缩放。

### 3.6 握持朝向（修已知问题 2）

弩的"朝前"应该是**弩身长轴 = 角色前方（-Z）**，弩臂水平展开。现在偏斜是因为直接继承了大剑"剑尖朝上"的绑定向。

建议按这个顺序调（每步出一张图）：
1. 先让弩身长轴对 -Z，臂展沿 X
2. 再调仰角：`-3°`（略上抬，瞄准时可读）
3. 最后调前后位置：让握把落在掌心，不是浮在手心外

## 四、斧设计

### 4.1 两条路的取舍

| | A 程序化拼 | B 用 `Axe_LP` | C 下载低模 |
|---|---|---|---|
| 工期 | 1 天 | 0.5 天 | 0.5 天 |
| 贴图 | 复用 256 三平面 | 4K 写实 C/N/V，**与全场 256 手绘风冲突** | 需重接 |
| 比例 | 我按 Q 版调 | 写实雕刻，和 4.5 头身主角**很可能不搭** | 需再调 |
| 管线一致 | ✅ 与全项目一致 | ❌ 引入外部网格 | ⚠️ 半外部 |
| 可复现 | ✅ 改数重跑 | ⚠️ 一次性导入 | ❌ |

**建议 A**。理由不是"我擅长"，而是：你的场景、道具、贴图、骨架全是代码造的，`Axe_LP` 是这套体系里唯一的"外来写实件"，它会立刻显眼。

B 可以留作对比图，看完再否。

### 4.2 尺寸

角色 4.5 头身，斧刃不能宽过肩。

| 部位 | 尺寸 | 说明 |
|---|---|---|
| 总长 | **0.92m** | 短柄战斧，不是长柄斧（长柄在俯视角下会被身体挡住） |
| 柄长 | 0.76m，直径 0.042m | 略扁椭圆（0.042×0.036），防"圆棍"感 |
| 刃宽 | **0.40m** | 关键：0.55 会遮住半个身体 |
| 刃高 | 0.28m | |
| 刃厚 | 0.012m 根 → 0.003m 刃口 | 楔形收薄 |
| 背钩 | 0.11m | 反向小钩，破甲的视觉暗示 |
| 配重环 | 柄尾 1 个 | 0.05 直径 |

### 4.3 几何拆解

| 件 | 做法 | 面数 |
|---|---|---|
| 斧刃（主刃） | `ArrayMesh` 直面：4 个侧棱 + 前后两个梯形面 + 刃口倒角 | ~120 |
| 斧颈（连接刃与柄） | 上下两段截锥 `CylinderMesh`（上细下粗） | ~40 |
| 斧柄 | `CylinderMesh` 8 边 + 轻微弯曲（2 段折线） | ~60 |
| 缠绳（握把段） | 4 圈薄 Torus，间距 0.06 | ~120 |
| 背钩 | 3 段短 Box 折成钩 | ~40 |
| 配重环 | Torus | ~40 |
| 楔片（柄顶铁楔） | 薄 Box ×2 交叉 | ~24 |

合计约 450 面，比一把剑（11k 面）轻得多。

### 4.4 剪影设计（这一条决定它像不像斧）

俯视 55° 是主视角，**能看见的是刃的顶面和柄的侧面**。所以：

- 刃必须是**不对称单刃**（一侧宽一侧钩），对称双刃在这个角度看着像"蝴蝶"
- 刃的顶面要有一道**脊线**（把顶面分成两个斜面），俯视时靠明暗能读出厚度
- 柄要有**粗细变化**（握把处细、两端粗）

### 4.5 材质

| 部位 | 材质 |
|---|---|
| 斧刃 | `iron_rust`（tint 偏冷，刃口 20% 区域 tint 提亮 → 磨亮感） |
| 斧颈 / 背钩 | `iron_rust`（暗） |
| 斧柄 | `wood_dry` |
| 缠绳 | `cloth_rot` |
| 楔片 / 配重环 | `iron_rust`（tint 0.7 暗） |
| 烬纹 | 刃口一道暗红 emission（`0.55,0.10,0.08`，energy 1.4），**只在满蓄力时点亮**（接 `charge_changed`） |

刃口的暗红只在蓄力时亮，是把设计文档里"斧满蓄 = 拖红痕"落到几何上的最省做法——不用做拖尾特效。

## 五、三把武器的共存规则

| 规则 | 内容 |
|---|---|
| 单一手部挂点 | 都挂在 `WeaponAttachment` 下，各自 pivot |
| 互斥显示 | 由 `player_visual.gd::_apply_weapon_visual` 控制，改成按 `Axe` 节点名判断 |
| 剑特殊 | 剑是蒙皮的，不在 pivot 里；切换时只切 `visible` |
| 缩放独立 | 每个 pivot 可独立 scale，方便单独微调（弩现在偏大，直接 ×0.9） |
| 碰撞体积 | 三把都用同一套判定（`tuning.json` 的 range/arc），**模型大小不影响判定** |

## 六、烬纹颜色：一并解决"绿 / 青 / 暗红"三色问题

`CHARACTER.md` 已知问题 1：模型自带绿辉光，设定是暗红。

现在场上有三个颜色：剑的**绿**、弩的**青**、设定里的**暗红**。新武器如果用暗红，会让这个矛盾更显眼。

| 选项 | 做法 | 代价 |
|---|---|---|
| **A（建议）** | 两把新武器用暗红；剑的绿暂不动，在设定里给个解释（"冷烬"：未燃的烬纹是青绿，愤怒/蓄力才是暗红） | 只改文档，不改资产 |
| B | 把剑的材质 emission 改成暗红 | 要改 `rogue_knight_v2.tscn` 的材质，可能影响整体观感，需对比图 |
| C | 全部统一成暗红（含弩） | 改动最大 |

A 最省，而且"青绿=冷烬、暗红=燃烧"本身是个好设定：**蓄力时从绿变红**就是天然的视觉反馈。

## 十、实施记录（2026-11-26 01:26–01:40）

按 P1–P3 做完了，产物在 `scenes/player/rogue_knight_v2.tscn`（**已备份**到 `dist/_backup/rogue_knight_v2.012623.tscn`）。

### 做法：不重生成骨架，只打补丁

没有跑 `build_rig_v2.gd`（它会重建整个场景，冒着丢动画的风险）。新写 `tools/build_weapons.gd`：
`load` 场景 → 删旧 Crossbow → 挂 `XbowPivot` / `AxePivot` → 建新弩/新斧 → `pack` 存回同一路径。

**它只碰节点，动画库一个字节没动**——自检确认改前 9 段、改后仍 9 段，`Cube_009`（剑）未受影响。

### 两个挂点角度（靠扫描定出来的）

| pivot | 最终值 | 说明 |
|---|---|---|
| `XbowPivot` | `(-90, 0, 0)` | 原值 (0,180,0) 时弩是**竖着**的 |
| `AxePivot` | `(90, 0, 0)` | 原值 0 时刃朝角色**后方** |

方法：`tools/_pivot_sweep.gd` 一次渲 6 组角度成对照表，肉眼选（这个脚本已删，逻辑就是改 pivot 的 `rotation_degrees` 再逐张截）。

### 一个必须改的技术点：三平面要换空间

`KitArt` 给的是 **世界空间**三平面（`uv1_world_triplanar = true`），那是给静止场景件用的。
武器会跟着手走，用世界空间会让贴图在刀身上**滑动**。所以 `_obj()` 里统一改成：

```gdscript
m.uv1_world_triplanar = false
m.uv1_triplanar = true
```

### 连弩：6 件 → 25 个节点

新增：弩机（扳机室）、扳机、扳机护圈、瞄具、箭槽两条侧壁、前段弩臂座、3 圈绑绳、弩头锥。
弩臂改成**每侧 3 段递进转角（12°/28°/46°）+ 端头**，做出弧与后掠；弦用 `_beam()` 从端头拉到后钩。
臂展收到 **0.476m**（原 0.54），弩身 0.38m。

### 斧：从零建，15 个节点

`SurfaceTool` 挤出 8 点贝旦斧剖面，厚度从 14mm 收到 2.5mm；柄 0.80m（略扁）、两段斧颈、背钩 2 段、4 圈缠绳、柄顶铁楔、柄尾配重环、刃根一道烬纹。
握把在**原点**（y=-0.30…+0.50），所以 pivot 直接就是手心。

### 烬纹

按方案 A：新武器用暗红 `Color(0.55,0.10,0.08)`，energy 1.2；剑的绿未动（留"冷烬→燃烧"的设定解释）。

### 实测

| 项 | 结果 |
|---|---|
| 武器总三角面 | **1588**（弩+斧；剑本身是 11k，对比下可忽略） |
| 动画片段 | 改前 9 / 改后 **9** |
| `player.tscn` 实例化 | OK，剑/弩/斧三节点都在，播放 `idle` |

### 还没做

### 附带观察

- 实机 ortho 12 下角色只占屏高约 15%，武器约 35–45px：弩的"弓臂+弦"剪影**能认出来**，斧认不出来。细节（箭槽、扳机护圈、绑绳）在这个尺度全部看不见。
- 弩身铜绿偏绿、紧挨着剑的荧光绿，两个绿叠在一起；斧刃之所以"发绿"，一半是剑的 emission 反光。

### 建议的修法（都还是改数重跑，不引入外部网格）

1. 弩整体上移 8.5cm（或把握把移到原点），让拳心落在握把上。
2. 弩箭 y 0.052 → 0.0615，箭槽侧壁压到弩身顶面以下，形成真槽而不是"盖板"。
3. 弩臂改成链式：每段起点 = 上一段终点，旋转角 12°/28°/46° 不变。
4. 斧刃整体下移 0.20，柄顶插进刃根；补一个 0.05×0.06×0.03 的斧眼（套筒）。
5. 斧轮廓重画：柄轴→刃口收到 0.24，刃口弧高提到 0.30，下方加 beard；顶面加一道脊线（两个斜面），俯视靠明暗读出厚度。
6. 烬纹改成 3mm 细线，常驻 emission=0，只在 `charge_changed` 满蓄时点亮。
7. 接入：`WEAPON_COUNT = 3` + `_apply_weapon_visual()` 加 Axe 分支 + 把 `attack_axe` / `charge_hold_axe` 合进场景。

1–4、6、7 大约 1 小时；5 是"像不像斧"的关键，单独一轮。

## 十三、外部连弩模型评估（2026-11-26 02:4x）

两个外部文件都试过了，结论：**OBJ 不能用，FBX 能改着用，但都不建议直接打包进游戏**。

| | 3d66 蒸汽朋克弩（FBX） | 诸葛连弩（OBJ，Tripo 生成） |
|---|---|---|
| 文件 | 24.4 MB（贴图内嵌） | 139.6 MB |
| 三角面 | **6 094** | **2 001 014** |
| 材质 | 5 个，各 2048² albedo（内嵌 15 张贴图） | 1 个，4×4096² PBR |
| 尺寸 | 1.332 × 1.074 × 1.258 m | 1.000 × 0.266 × 0.664 m |
| Godot 导入 | 正常，但只接了 albedo（normal/rough 没连） | MTL 解析失败，材质丢失，渲出来是白模 |
| 观感 | 手工感、雕花清晰 | "锡纸"：4K 贴图压在 200 万面噪点网格上 |

对比基准：本项目三把武器合计 1 588 面，剑 11k。

### 为什么 FBX 也不建议直接用

1. **比例与轴**：模型原点在弩臂一侧，握把在尾端 0.6m 处。缩到 0.375 装到手上时，手抓在弩臂根部、握把悬空（见 `review/trial_xbow_0.png`）；转 180° 弩臂平面又变竖直。要重设 pivot + 轴。
2. **材质**：5 套 2048² 贴图 = 5 个 draw call、约 60 MB 显存；全场是 256 三平面手绘，直接换会立刻"贴"上去。要重做得走 `assets/materials/` 那套 256。
3. **剪影**：实机 ortho 12 下武器约 40px，雕花全部糊成黑块；弩臂又是尖角外翻，远看像斧头。
4. **授权**：3d66 素材通常限单项目、不可再分发；爱给网免费模型多为"仅限学习交流"。参赛作品要公开/评奖，直接打包有风险。

### 建议

- **推荐**：只借"形"。把它三个可读特征 —— 红宝石核心、黄铜箍、翼形弩臂 —— 搬进现有程序化弩（约 +200 面，1–2 小时），风格和面数都不破。
- 若一定要用 FBX：缩到 0.42–0.46m、重设 pivot 到握把、材质改 256 三平面、删掉 60% 尖角雕花、确认授权，约半天。
- OBJ 不建议任何形式的直接使用（要重拓扑到 2k 面才有意义）。

## 二十二、持续射击保持瞄准态（方案 A，2026-11-26 12:3x）

### 根因

1. `fire_xbow` 长 0.70s，**整段都是瞄准姿态**（t=0 就是 0.0°，只有 0.09s 处 5.6° 后坐），`loop_mode=0`。播完 `player_visual` 把 `_current` 清空，下一帧按速度切 `idle`（−24°/−16°）→ 看起来"回正"。
2. `_attack_pressed()` 用的是 `is_action_just_pressed`，**长按只有第一发有动画**；后续连发由 `player.gd` 的冷却驱动，没有动画。

### 改了三处

| 文件 | 改动 |
|---|---|
| `rogue_knight_v2.tscn` | 从动画包合并 `aim_walk`（1.1s, loop）→ 场景 9 段变 10 段 |
| `player.gd` | 新增 `signal fired`，`_do_ranged` 成功生成子弹后 emit |
| `player_visual.gd` | 新增瞄准态：`_is_aiming()` = 拿弩 and (按住 attack 或 距上次开火 < 420ms)；静止播 `aim_xbow`，移动播 `aim_walk`；`fired` 信号驱动每发后坐（只播 0.30s 后交回状态机，避免整段 0.70s 锁腿）；给 aim 片段补 0.14s 混合时长 |
