# 17 武器与蓄力设计计划

> 范围：**斧 / 剑 / 连弩** 三武器 + **蓄力（charge）** 机制。
> 本文只做设计，**不改任何代码、场景、资源**。所有结论都基于实测：`tools/_asset_probe.gd`（29 个 FBX）、`docs/16_模型素材清点.md`、现有 `player.gd` / `player_visual.gd` / `build_anim_v2.gd` / `data/tuning.json`。
> 一句话结论：**这套设计不需要下载任何新动画**，斧的动作、蓄力循环都能从手上已有的 FBX 生成。

## 二、三武器定位

三把不是"数值不同的同一把"，是三种**承诺时长**。

| | 剑 · 刃守 | 斧 · 破门者 | 连弩 |
|---|---|---|---|
| 定位 | 节奏武器 | 读招武器 | 压制武器 |
| 有效距离 | 2.7m，弧 110° | 2.4m，弧 70° | 全屏直线 |
| 单次承诺 | 0.42s | 2.10s（蓄 1.2 + 放 0.9） | 0.26s/发 |
| 打谁 | 群（1v3 的杂兵） | 精英（brute / 有盾） | 远程（shooter）、打断蓄力 |
| 蓄力上限 | 0.45s，**可移动** | 1.20s，**移速 ×0.3** | 无蓄力（按住连发） |
| 满蓄奖励 | 弧 110°→130°、击退 ×1.2、硬直 +0.12s | 破防 + 硬直 0.5s | — |
| 主要风险 | 按住期间不能连砍（纯时间成本） | 蓄力时走得慢 | 无（持续压制） |

> **本次修订（第 2 版）：取消一切自伤。** 满蓄只有收益，代价只有"时间"——蓄力时你没法同时移动和连砍，这在 1v3 里本身就是风险，不需要再额外扣血。原案里"烬纹过载自伤 8% 换 1.6×"及"过蓄下坠被反击"两条**全部移除**。

对应到卡口 1v3：剑清杂兵、斧拆精英、弩点名射手。三把都要能"读"——敌人的 `windup_sec`（grunt 0.45 / brute 0.65）就是给玩家换武器+蓄力的窗口。

## 三、蓄力系统

### 3.1 状态机

```
IDLE ──按住 attack──> WINDUP(0.12~0.18s) ──> HOLD(循环) ──松开──> RELEASE ──> RECOVERY ──> IDLE
                                                │
                                                └── 到 full_sec 就封顶：继续按住只是维持满蓄，
                                                     不再增长，也不产生任何惩罚
```

三条硬规则：

1. **按住蓄、松开放**。和连弩的 hold-to-fire 同一套输入语义，玩家不用学第二套。
2. **蓄力只对近战生效**。`attack` 在剑/斧状态下是"按住"；在弩状态下保持现在的按住连发。这条边界必须在 `_update_attack` 里分清，否则弩会被蓄力卡住。
3. **没有过蓄惩罚**。`ratio` 在 `full_sec` 封顶，之后按住只是维持；松开照常放出。状态机因此**只有 4 个状态**（WINDUP / HOLD / RELEASE / RECOVERY），不需要 OVERCHARGED 分支——少一个状态就少一类 bug。

### 3.2 参数（写进 `tuning.json`，全部新增键，不动现有键）

```jsonc
"weapons": {
  "blade": { "...现有 7 个键不动...",
    "charge": {
      "min_sec": 0.10, "full_sec": 0.45,
      "move_mult": 1.0, "turn_mult": 0.6,
      "damage_min": 1.00, "damage_max": 1.35,
      "range_add": 0.0,  "arc_add": 20.0, "knockback_max": 1.2,
      "release_sec": 0.60, "stagger_add": 0.12
    } },
  "axe": {                                  // 新增整块
    "damage": 30.0, "startup_sec": 0.20, "active_sec": 0.14, "recovery_sec": 0.56,
    "range": 2.4, "arc_deg": 70.0, "knockback": 9.0,
    "charge": {
      "min_sec": 0.15, "full_sec": 1.20,
      "move_mult": 0.30, "turn_mult": 0.50,
      "damage_min": 1.00, "damage_max": 2.20,
      "range_add": 0.2, "arc_add": 0.0, "knockback_max": 2.20,
      "release_sec": 0.90, "guard_break": true, "stagger_add": 0.50
    } }
}
```

`charge_ratio = clamp((held - min_sec) / (full_sec - min_sec), 0, 1)`，之后所有 `*_min → *_max` 都按这个比例插值。这样**蓄力曲线调一个数就能改整体手感**，不用改代码。

注意参数表里**没有任何 `self_damage` / `overcharge` / `punish` 键**——惩罚只体现在 `move_mult` 和"按住不能连砍"这两件事上，两者都从机制里自然长出来，不靠额外规则。

### 3.3 分四层实现（每层只碰一个文件）

| 层 | 文件 | 改动 |
|---|---|---|
| 数据 | `data/tuning.json` | 加 `weapons.axe` 整块 + 两把近战的 `charge` 子块 |
| 逻辑 | `scripts/player/player.gd` | `WEAPON_COUNT` 2→3、`WEAPON_AXE`、`WEAPON_LABELS` 加"斧"、`_read_tuning` 读 charge、`_update_attack` 拆三条分支、`_begin_swing(charge_ratio)`、新信号 `charge_changed(ratio, stage)` |
| 表现 | `scripts/player/player_visual.gd` | 新 clip 选择：`charge_hold_axe` / `charge_hold_blade`、`attack_axe`；`_apply_weapon_visual` 加斧的显隐 |
| 生成 | `tools/build_anim_v2.gd` | 新增 3~4 段 clip（见第四节）+ **一个源选择修正**（见 4.1 的坑） |

输入层只需在 `scripts/autoload/tuning.gd` 的 `KEY_BINDINGS` 加 `"weapon_3": KEY_3`；HUD 的 `WEAPON_HINTS`（第 29–31 行）同步加一条。

### 3.4 hold 循环怎么生成（零下载，这是全案的关键）

**取帧**：`Great Sword Slash` 的 `t = 0.30s`——正好是举器过头的最高点（现有 `attack_blade` 裁前摇就是从 0.30 起，CHARACTER.md 有记录）。

**生成** `charge_hold_axe`（剑版同理，振幅更小）：

```
length = 0.60s, loop = LOOP_LINEAR
每根骨的局部旋转 = 源帧(t=0.30) 的局部旋转 × sin(2π·t/0.60) × 振幅
  Hips            : 位移 y ±0.010 m
  Spine, Spine1   : pitch ±1.8°
  RightArm/ForeArm: roll  ±1.2°
  Head            : pitch ±0.8°
```

剑版：`length = 0.40s`，振幅全部 ×0.45。

**满蓄提示（不发呆的关键）**：`ratio ≥ 1` 后不换 clip，只把**振幅 ×1.8、频率 ×1.6**（用 `AnimationPlayer.speed_scale = 1.6` 就够，不用重新生成），再加一层武器发光。玩家看到"开始抖了"就知道满了——这比 UI 进度条更直接，也更省事。

### 3.5 释放

`release` 不重新采样，直接播 `attack_axe`，按 ratio 改三处：

- 时长：0.65s → 0.90s（`speed_scale = 0.65/0.90`，0.72×）
- 命中窗后移：`startup_sec`：0.20 → 0.32
- 伤害/击退：按 3.2 的 `damage_max` / `knockback_max` 插值

**破防**：`brute.knockback_resist = 0.75`、`boss = 0.95`，现有公式里击退会被乘掉。满蓄斧应绕过 resist——给 `take_damage` 加一个可选的 `ignore_resist` 参数，只在 `guard_break == true` 时传 `true`。这是斧"能拆精英"的唯一实现路径，不改这条，满蓄斧对 brute 只是"伤害高一点的剑"。

### 3.6 惩罚清单：只有 3 条，全部是"自然成本"

| # | 惩罚 | 强度 | 为什么保留 |
|---|---|---|---|
| 1 | 蓄力期间不能连砍 | 无感知 | 不是惩罚，是机制本身——一次蓄力只出一次刀 |
| 2 | 斧蓄力时移速 ×0.30（剑 ×1.0） | 轻 | 唯一实质风险：1v3 时站在原地 1.2s 会被围 |
| 3 | 蓄力被打断（受击）→ 蓄力清空 | 轻 | 不需要额外规则，受击本来就中断一切动作 |

**明确不做的**：

- ❌ 自伤（原"烬纹过载 8%"）——已删除，见 §十 第 6 条
- ❌ 过蓄惩罚（下坠 / 自动放出 / 被反击窗口）——已删除
- ❌ 蓄力消耗体力/耐力——项目没有耐力系统，不为一个武器引入新资源条
- ❌ 松早了"白蓄"——`ratio < min_sec` 时按普通攻击结算（倍率 1.0），不算失败
- ❌ 蓄力期间禁止转向——斧保留 `turn_mult 0.50`，还是能回头，只是慢

**设计原则**：惩罚只从"时间"这一件事派生。玩家蓄得越久，站得越久——这个代价已经在战斗里了，不需要再扣血、扣资源、或者做个"蓄爆了"的惩罚动画。

### 4.1 ⚠️ 一个必须先修的坑

`build_anim_v2.gd::_load_src()` 第 122–123 行取的是 `ap.get_animation_list()[0]`。对**纯动作文件**（`mesh=0`）没问题——里面只有 `mixamo_com` 一段。但 `Jump Attack.fbx` 是**模型+动作混合包**，实测有两段：

```
Take 001     3.33s   ← 内嵌角色的静帧，先被返回
mixamo_com   3.80s   ← 真正的跳劈
```

所以 `[0]` 会拿到 3.33s 的静帧，生成出来的是一段**不动的**攻击——而且不会报错，只会"看起来没做"。同一问题也存在于 `Mutant*` 系列（若以后用来当敌人动作）。

修法：`_load_src` 改为按名字优先取 `mixamo_com`，找不到再退回 `[0]`。这是本次唯一"必须先做"的底层修正。

### 4.2 剑与斧的动作差异化（否则玩家分不出拿了什么）

| | 剑 | 斧 |
|---|---|---|
| 躯干横扫 | 46°（现有） | 72° + 18° 下压 |
| 命中窗 | 0.035 / 0.09（现有） | 0.20 / 0.14（起手慢、判定短） |
| 收招 | 0.295s | 0.56s |
| 收势 | 剑停在侧前方 | 斧劈到地面，重心前压 |

同一个源 clip，靠"裁剪区间 + 躯干角度 + 时窗"三件事就能长得完全不像——这也是为什么不需要为斧单独找动作。

## 五、斧的模型怎么办

### 方案 A（默认，0 下载）

`assets/anim_src/bulky-knight/source/Big Night For Sketchfab.fbx` 里有 `Axe_LP` 网格。需要三步：

1. **缩放**：实测 AABB `0.00 × 0.06 × 0.03`（单位是 cm 级），按刃宽目标 0.55m 反推缩放系数（约 ×18，具体以导入后实测为准）
2. **对轴**：长轴对齐 `socket_weapon.R` 的 +Y，刃口朝角色右前；参考大剑 `Cube_009` 当前的 socket 局部变换
3. **贴图**：`Axe_C / Axe_N / Axe_V` 三张 4K 分离式（albedo / normal / 打包），`_V` 里通常 R=AO、G=Roughness、B=Metallic，需拆通道接 `StandardMaterial3D`

### 风险与决策点

`Axe_LP` 是**写实雕刻**（4K 贴图），主角 Rogue Knight 是 4.5 头身手绘 Q 版。**风格很可能不搭**——这一点不实测说不准。

所以方案 A 的第一步不是接线，是**出一张 1:1 对比图**（斧在大剑位置、同镜头同光照），看完再决定。若不合，走方案 B。

### 方案 B（备选，需下载模型，不需下载动作）

KayKit / Quaternius 的低模武器包（CC0），风格与已在用的 KayKit 地牢包一致。**只换模型，动作仍是第四节生成的那几段**，所以换模型的代价只有"重新对轴"。

## 七、数值影响（必须先算清，否则会破坏现有平衡）

现有：`grunt.hp = 46`、`blade.damage = 26`。

- 剑：`26 × 1.35 = 35.1` → **满蓄也秒不掉 grunt**，需要两下。这是对的：剑的价值在速度和范围，不在单发爆发。
- 斧：`30 × 2.20 = 66` → **满蓄一击杀 grunt**。

这是**故意的**：斧要付 1.2s 蓄 + 0.9s 放 = 2.1s 的承诺，换一个杂兵，效率上并不占优（剑在这 2.1s 里能砍三下）。但对精英（brute 170hp）时，斧的 `guard_break + stagger 0.5s` 才是它的价值，而不是对杂兵的数字。

**没有自伤之后，平衡靠这三条线立住**（全部是"多给/少给"，不是"扣血"）：

1. 剑满蓄不秒杂兵 → 剑不会因为蓄力变成"更慢但更强"的斧
2. 斧满蓄才秒杂兵 → 想要那个爆发必须付 2.1s
3. 斧不蓄力 `30` 两下杀 grunt，比剑慢 → 平砍不是万能解

**要盯的一条线**：不要让斧的"平砍"（不蓄力）变成万能解。不蓄力时 `damage × 1.0 = 30`，两下杀 grunt，速度还不如剑——这个关系是对的，实现时别调歪。

## 十、待你拍板的 5 件事

1. **斧是第三把武器（按 3）还是替换剑？** 建议第三把——三把各自对应一种敌人，卡口 1v3 才有换武器的理由。
2. **蓄力是"按住蓄/松开放"还是"按一次进蓄力态、再按一次放"？** 建议前者，与连弩的 hold-to-fire 一致，玩家只学一套。
3. ~~斧要不要过蓄惩罚~~ → **已按你的要求取消**（§3.6）。如果你还想要一点紧张感，建议只做纯表现：满蓄 3s 后镜头极轻晃（`Juice` shake 0.03），不做任何机制扣减。
4. **满蓄斧一击杀 grunt 能接受吗？** 建议接受（这是斧唯一的爽点），P2 后用 `fight_probe` 实测卡口 1v3 耗时，若清怪太快就把 `damage_max` 降到 1.9。
5. **斧模型走 A（`Axe_LP` 写实 4K）还是 B（找低模）？** 建议先出 A 的对比图再定，不要先接。
