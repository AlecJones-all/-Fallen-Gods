# 18 · 战斗与 UI 可执行规格（MVP v1.0）

> **状态：现行、强制。** 本文将 15 的核心玩法、16 的关卡/Boss、17 的视觉方向转写为可实现、可测试的规则；出现冲突时，本文件在“战斗状态、输入、运行时逻辑、UI 布局、验收”范围内优先。
>
> **目标版本**：Godot + H5，一周可玩 MVP。验收关卡为第 1–3 关及第 5 关 Boss；第 4–15 关为沿用同一契约的内容规划，不构成本轮必须完成范围。

- 只参考“横屏弹球清怪、底部玩家/上部敌群、边栏构筑、可读反弹反馈”的**功能范式**。
- 必须原创：角色、敌人、Boss、砖块表情、图标、字体、面板边框、配色、音效、动画节奏、关卡摆布、文案与全部源素材。
- 禁止：截取、拆包、重绘、描摹或复用参考游戏的素材、UI 纹理、字体、音频、角色、关卡截图及可识别的 UI 组合。
- 本项目视觉母题为“希腊废墟 + 深坑封印”：黑曜石、暗金、青蓝净礼光；不得使用参考截图中的棕红铜框、特定图标排列或血条装饰作为设计目标。

## 1. 运行状态机

### 1.1 唯一状态集合

```text
LOAD → STORY_INTRO → COMBAT ↔ LEVEL_UP
                      ↕
                    ALTAR
COMBAT → BOSS_INTRO → BOSS_COMBAT → STORY_OUTRO → SETTLEMENT
COMBAT / BOSS_COMBAT → DEAD → RETRY | EXIT_TO_MENU
```

| 状态 | 允许输入 | 时间与实体 | 退出条件 |
|---|---|---|---|
| `LOAD` | 无 | 不模拟 | 配置、存档、场景完成加载 |
| `STORY_INTRO/OUTRO` | 推进/跳过已读文本 | 战斗实体冻结且隐藏 | 文本结束 |
| `COMBAT` | 移动、瞄准、发射、暂停 | 全部实体按 1.0 倍速模拟 | 经验满、净礼节点、Boss 阈值、死亡 |
| `LEVEL_UP` | 三选一 | **所有战斗实体与计时器冻结** | 选择一项后回到 `COMBAT` |
| `ALTAR` | 购买/跳过 | **所有战斗实体与计时器冻结** | 成功选择或跳过 |
| `BOSS_INTRO` | 无 | 战斗冻结；最长 1.0 秒 | 演出完成，进入 `BOSS_COMBAT` |
| `BOSS_COMBAT` | 移动、瞄准、发射、暂停 | Boss、玩家、既存小怪和敌弹继续模拟；禁止普通墙继续生成 | Boss 特殊胜利、Boss 死亡或玩家死亡 |
| `SETTLEMENT` | 商店、继续 | 战斗实体销毁；不得再掉落资源 | 结算完成 |
| `DEAD` | 重试/退出 | 战斗实体冻结，不能再获取经验/资源 | 选择重试或退出 |

### 1.2 同一物理 tick 的结算顺序

1. 读取移动与瞄准输入；仅在 `COMBAT` 或 `BOSS_COMBAT` 接受发射。
2. 移动玩家；移动现有弹球、敌弹、砖块、Boss。
3. 对每颗玩家弹球依次处理：墙体 → 砖块/精英 → Boss 附属目标 → Boss → 玩家反弹面 → 底部回收。
4. 处理敌弹与敌人接触对玩家造成的伤害。
5. 结算死亡；玩家 HP `<= 0` 时，死亡优先于升级、净礼和 Boss 入场。
6. 结算本 tick 的击杀、经验、Ichor、残片与关卡进度。
7. 若经验达到阈值，进入 `LEVEL_UP`；否则按进度触发 `ALTAR` 或 `BOSS_INTRO`。

## 2. 输入、发射与弹球契约

### 2.1 输入

| 平台 | 移动 | 瞄准/发射 | 取消 |
|---|---|---|---|
| PC | WASD / 方向键 | 左键按下显示瞄准线，松开时发射 | 右键或 Esc 取消蓄力 |
| 触屏 | 左下虚拟摇杆 | 战斗区右半屏按住拖动，松开时发射 | 位移小于 12 逻辑像素时取消 |

- HUD、弹窗与暂停层必须吞掉指针事件，不得透传为发射。
- 有效发射角度为 `-160° 至 -20°`（向上半场）；超出范围时将瞄准线钳制到最近有效角。
- `COMBAT` 与 `BOSS_COMBAT` 外不得显示瞄准线、不得生成弹球。
- 玩家移速为 15 号规定的 `300 px/s`，神速修正仍按 15 号 10.5 计算。

### 2.2 发射规则

- 每次有效松开只产生一组齐射；齐射数量 = 当前弹球数，初始 1、上限 6。
- 齐射以玩家瞄准方向为中心：1 球无偏移；2–6 球在 `±15°` 内等距分布。
- 每颗球初速度 `400 px/s`，判定半径 `6 px`，初始反弹次数 3、上限 8。
- 远程弹珠只由本节手动发射触发；**不得自动锁敌、自动瞄准或按攻击间隔自行发射**。
- 长矛球等近战弹珠可按各自攻速自动挥击，但不得替代手动远程发射的核心循环。

### 2.3 碰撞、反弹与伤害

- 球与墙、可反弹砖块、Boss、封印节点、玩家反弹面发生一次有效镜面反射时，反弹次数 `-1`；降至 0 立即销毁。
- 球触及战场底边且未命中玩家反弹面时立即回收，不扣玩家生命。
- 同一球对同一目标的再次伤害冷却为 `0.12s`；冷却内可反弹但不重复伤害。
- 穿透球：命中目标时伤害生效但不反弹、不扣反弹次数；其最大可穿透目标数以 15 号数值为准。
- 分裂球：首次有效命中后生成 3 个子球，每个子球伤害为母球 50%，不可再次分裂；子球继承母球当时剩余反弹次数。
- 连锁球：首目标命中后仅可额外寻敌 2 次；候选按距离升序取最近未命中过的活目标，半径为 96 px。
- 所有有效反弹均须显示火花和短拖尾；命中须显示伤害飘字；击杀须有碎裂反馈。

## 3. 砖块墙、进度、经验与升级

### 3.1 关卡进度

- 一关的普通推进进度总值为 100；普通砖块贡献 1，精英贡献 5。Boss 只在 `progress >= 100` 且场上普通砖块、精英均已清除后入场。
- 普通砖块墙由多行构成，从战场上方生成并向下移动；每行数量取对应关卡 `density`，不足的格位随机留空但每行至少保留 `ceil(density × 0.7)` 个砖块。
- 每 2.5 秒尝试生成一行；场上未死普通砖块达到 `density × 3` 时暂停生成；第 1–3 关墙体下移速度为 `12 px/s`。
- 普通砖块触及玩家底部危险线（y=300）时，对玩家造成一次该关小怪伤害并销毁；不使用“漏接扣分”。
- `progress >= 100` 后停止普通墙生成；若该关有 Boss，进入 `BOSS_INTRO`；无 Boss 的关卡在清场后进入 `SETTLEMENT`。

### 3.2 经验

| 来源 | 经验值 |
|---|---:|
| 普通砖块 | 1 |
| 精英 | 5 |
| Boss | 20 |

- 第 `n` 次升级所需经验为 `10 + 5 × (n - 1)`；升级后保留溢出经验。
- 经验自动吸附到玩家，不生成可错过的拾取物。
- 同 tick 多次升级时，每次选择完成后先检查溢出经验；仍满足阈值则再次进入 `LEVEL_UP`。

### 3.3 三选一卡池

- 三选一固定提供 3 个互不重复的候选；候选类别权重为：未拥有弹珠 40%、已有可升级弹珠 25%、未拥有饰品 20%、已有可升级饰品 10%、属性点 5%。
- 已满 3 级的弹珠/饰品必须从池中排除；槽位已满时，不再提供新的同类物品，只能提供已拥有且未满级项。
- 每个候选先抽类别，再从该类别的合法项中等概率抽取；类别无合法项时按上述顺序循环重抽，最多 8 次。
- 8 次后仍不足 3 项时，用未达软上限的属性点补齐；全部属性也满上限时，提供 `Ichor +20` 作为最后补位。
- 不设重抽、不设选择超时；升级界面必须显示物品效果、当前等级、升级后的数值。

## 4. Boss、净礼坛与重试

- 关卡数值、精英/Boss 倍率及五场 Boss 的特殊胜利条件以 15、16 为准；第 10 关生存 30 秒、第 15 关摧毁 4 个封印节点均不得视作“清空 Boss HP”。
- 每关仅生成一次净礼坛，位置为 Boss 前或进度 80 时；激活后进入 `ALTAR`。净礼/治疗/强化价格与数值以 15 号 10.4 为准。
- 死亡后“重试当前关”必须重建随机 seed、关卡进度、局内构筑、污秽与当局 Ichor；已解锁关、七境、基地、已读剧情与跨关卡组保持不变。
- 结算完成才允许写入通关和永久资源；死亡途中不得写入当前局临时资源。

## 5. UI 可执行布局（640 × 360 逻辑坐标）

### 5.1 区域与层级

| 区域 | 逻辑坐标 | 内容 | 层级 |
|---|---|---|---:|
| 顶部状态区 | `x=8..632, y=8..38` | HP、Ichor、经验条、关卡进度 | 100 |
| 左构筑轨 | `x=8..96, y=50..250` | 4 弹珠槽 + 4 饰品槽 | 110 |
| 中央战斗区 | `x=104..528, y=48..326` | 墙、Boss、敌弹、玩家球、瞄准线 | 0..50 |
| 右 Boss 轨 | `x=536..632, y=50..148` | Boss 名、HP/隔绝进度、阶段提示 | 110 |
| 底部操作区 | `x=104..528, y=286..352` | 玩家、瞄准线、移动/触屏提示 | 60 |
| 模态层 | 全屏 | 升级、祭坛、暂停、剧情、死亡 | 200 |

- 逻辑分辨率固定 `640×360`，只允许整数倍缩放；非 16:9 设备采用左右或上下留边，禁止裁切 HUD。
- 所有可点击控件逻辑热区不得小于 `44×44 px`；战斗区外的控件必须阻止发射。
- 数字显示：`0–999` 原样、`1000–999999` 显示为一位小数 `K`、更大显示为一位小数 `M`；禁止挤压或换行。

### 5.2 组件规则

- 弹珠槽和饰品槽各 4 个，单格 `40×22 px`，图标 `16×16 px`，等级数字置于右下；未获得为暗色空槽，满级显示 `MAX`，锁槽显示锁形原创图标。
- 经验条位于顶部中部，尺寸 `240×10 px`，必须同时显示“当前等级”和“当前/所需经验”。
- Boss 信息仅在 `BOSS_INTRO/BOSS_COMBAT` 显示。普通 Boss 显示名称、阶段、HP；第 10 关显示生存倒计时；第 15 关显示“隔绝进度 0–100%”。
- 升级、祭坛、死亡面板使用半透明黑曜石遮罩；打开后背景战斗冻结。选项卡最少 `180×68 px`，图标、名称、效果、等级都必须可见。
- 文字最小逻辑字号 12 px；关键信息不可仅靠色彩区分，必须配合图标、文字或形状。

## 6. 工程契约与性能

- 战斗使用固定物理步长 `1/60s`；随机数必须使用本局 seed，seed 写入调试日志并可由测试注入。
- “加速”只允许 `1× / 2×` 两档；升级、祭坛、暂停、剧情、死亡状态强制为 `1×` 或冻结，不得在模态层下加速。
- MVP 在 `1920×1080`、60 FPS 目标下，场上最多 90 普通砖块、12 精英、48 玩家球、80 敌弹；超出上限时拒绝生成新的低优先级实体，不得降低已有实体伤害结算准确性。
- 所有设计常量必须由数据文件读取；代码不得另写与 15/16/18 重复且不一致的魔法数。字段变更须同步更新数据说明和本节。

## 7. 验收清单

| ID | 可验收条件 |
|---|---|
| COMBAT-01 | 静止 10 秒且不操作时，远程弹珠不会自动发射或自动锁敌。 |
| COMBAT-02 | PC 鼠标与触屏均可显示瞄准线并在松开后发射；点击 HUD 不会发射。 |
| COMBAT-03 | 初始球在第 3 次有效反弹后回收；触底不造成生命扣减。 |
| COMBAT-04 | 同一球在 0.12 秒内不能重复伤害同一目标。 |
| PROG-01 | 关卡按进度、墙体和 Boss 阈值推进，不以“清波后波次结算”推进。 |
| BUILD-01 | 升级时世界冻结，三项候选合法且不重复；满级物品不能再次出现。 |
| BOSS-01 | 第 5 关击杀结算、第 10 关生存结算、第 15 关封印进度结算均与各自条件一致。 |
| SAVE-01 | 重试只清当局资源/构筑，永久进度不回退；未结算的当局 Ichor 不可带出。 |
| UI-01 | 在 640×360、1280×720、1920×1080 下，所有核心 HUD 不重叠、不裁切，且可读。 |
| IP-01 | 资产清单能说明原创来源；项目不包含参考游戏截图、素材、临摹 UI 或拆包资源。 |

## 8. 实施边界

- **始终执行**：每次实现前先对照第 7 节对应验收项；改动数据字段时同步更新文档与测试；新增资产必须登记来源。
- **需要先确认**：改变 15 的数值、增加依赖、修改存档格式、将次做项目纳入 MVP、改变五场 Boss 胜利条件。
- **禁止执行**：恢复自动远程发射/自动瞄准；恢复波次结算为主推进；以参考游戏的现成 UI 或素材替代原创设计；在未更新规格的情况下修改战斗行为。
